# SocialPulse Gateway (api_gateway)

![Build](https://github.com/socialpulse/api_gateway/actions/workflows/ci.yml/badge.svg)
![Coverage](https://img.shields.io/codecov/c/github/socialpulse/api_gateway)
![License](https://img.shields.io/github/license/socialpulse/api_gateway)
![Version](https://img.shields.io/github/package-json/v/socialpulse/api_gateway)

SocialPulse Gateway is an expert-level, **TypeScript-based API gateway** that sits in front of the SocialPulse micro-service constellation—`timeline`, `media`, `messaging`, `notifications`, and `social-graph`.  
It **federates REST and GraphQL endpoints** into a single programmable surface while enforcing strict [Clean Architecture](https://8thlight.com/blog/uncle-bob/2012/08/13/the-clean-architecture.html) boundaries.

Key focus areas include:

* high-fanout activity feeds & ranking rollouts
* real-time presence & conversations
* user-safety guardrails: rate-limiting & behavioral analytics
* zero-downtime versioning
* observability & self-documentation

## Features

| Domain                 | Capability                                                                                        |
| ---------------------- | -------------------------------------------------------------------------------------------------- |
| **Versioning**         | Path-based (`/v1`, `/v2`) & header-based negotiation (`X-Api-Version`)                             |
| **Response Caching**   | Smart fan-out cache via Redis with cache-stampede mitigation                                       |
| **Request Validation** | JSON Schema & GraphQL SDL validation, backed by Zod                                               |
| **Rate-Limiting**      | Token-bucket algorithm (Redis Lua, per user/IP/endpoint)                                          |
| **API Docs**           | OpenAPI 3 & GraphQL SDL, auto-generated by code annotations                                        |
| **Observability**      | Pino structured logging, Prometheus metrics, OpenTelemetry traces                                 |
| **Safety**             | Behavioral analytics plug-in to flag follow-spam / message floods                                  |

## Quick Start

### 1. Clone & bootstrap

```bash
git clone https://github.com/socialpulse/api_gateway.git
cd api_gateway
pnpm i
```

### 2. Provision local infra (Docker Compose)

```bash
# Starts Redis, Postgres (for config), and Jaeger for tracing
docker compose -f docker/docker-compose.dev.yml up -d
```

### 3. Seed `.env`

```dotenv
# .env.local
NODE_ENV=development
PORT=3000
GRAPHQL_PLAYGROUND=true

REDIS_HOST=localhost
REDIS_PORT=6379

TIMELINE_SERVICE=http://localhost:4001
MEDIA_SERVICE=http://localhost:4002
MESSAGING_SERVICE=http://localhost:4003
NOTIFICATION_SERVICE=http://localhost:4004
SOCIAL_GRAPH_SERVICE=http://localhost:4005
```

### 4. Run the gateway

```bash
pnpm dev
```

Navigate to  
* REST docs: <http://localhost:3000/docs>  
* GraphQL playground: <http://localhost:3000/graphql>

## Configuration

All runtime configuration is **12-Factor compliant** (environment variables) and type-safe (`src/config/schema.ts`).

```ts
// src/config/schema.ts
import { z } from 'zod';

export const ConfigSchema = z.object({
  NODE_ENV: z.enum(['development', 'test', 'production']),
  PORT: z.coerce.number().default(3000),
  GRAPHQL_PLAYGROUND: z.coerce.boolean().default(false),
  REDIS_HOST: z.string().nonempty(),
  REDIS_PORT: z.coerce.number().default(6379),
  // ...truncated
});
```

Invalid configuration fails fast on boot, preventing undefined behavior in production.

## Architecture

```
                    ┌──────────────────────────┐
                    │      Presentation        │
                    │ ──────────────────────── │
Incoming <-REST/───>│ Controllers / Resolvers  │<───> WebSocket Outgoing
Requests  GraphQL   │                          │
                    └──────────┬───────────────┘
                               │   CQRS
                    ┌──────────▼───────────────┐
                    │   Application Layer      │
                    │ Use-cases & DTO mappers  │
                    └──────────┬───────────────┘
                               │
                    ┌──────────▼───────────────┐
                    │      Domain Layer        │
                    │ Aggregates, VOs, Policies│
                    └──────────┬───────────────┘
                               │
                    ┌──────────▼───────────────┐
                    │   Infrastructure Layer   │
                    │ Adapters, Repositories   │
                    └──────────────────────────┘
```

Clean Architecture decouples business logic from delivery & persistence concerns, enabling:

* **Independent deployability** of downstream services
* **Pluggable transports** (HTTP, WebSocket, gRPC)
* **Deterministic testing** (pure domain layer)

## API Surface

### REST

```
GET /v1/timeline/{userId}
POST /v1/follow
PATCH /v1/reactions/{postId}
/docs  → OpenAPI 3 UI (swagger)
```

Sample cURL:

```bash
curl -H "Authorization: Bearer <token>" \
     -H "X-Api-Version: 2" \
     http://localhost:3000/timeline/123
```

### GraphQL

```graphql
type Query {
  viewerTimeline(cursor: String, limit: Int = 25): TimelineConnection!
}

type Subscription {
  newLike(postId: ID!): LikeEvent!
}
```

Live subscription (WebSocket):

```js
import { createClient } from 'graphql-ws';

const client = createClient({ url: 'ws://localhost:3000/graphql' });

client.subscribe(
  {
    query: 'subscription ($id: ID!) { newLike(postId: $id) { user { username } } }',
    variables: { id: 'post_42' },
  },
  {
    next: data => console.log(data),
    error: err => console.error(err),
    complete: () => console.info('completed'),
  },
);
```

## Development Guide

### Project Structure

```
src/
├─ adapters/           # Infrastructure adaptors (Redis, HTTP clients)
├─ application/        # Use-cases, DTOs
├─ config/             # Runtime configuration
├─ domain/             # Aggregates & value objects
├─ interfaces/         # REST controllers & GraphQL resolvers
├─ middlewares/        # Express middlewares (rate-limit, auth)
├─ server/             # App factory & server bootstrap
└─ shared/             # Common utils & types
```

### Important Commands

| Command            | Description                           |
| ------------------ | ------------------------------------- |
| `pnpm dev`         | Start server with hot-reload (ts-node)|
| `pnpm build`       | Compile TypeScript → `dist/`          |
| `pnpm start`       | Run compiled code                     |
| `pnpm test`        | Unit & integration tests (Vitest)     |
| `pnpm lint`        | ESLint + Prettier checks              |
| `pnpm format`      | Auto-format code                      |

## Testing

* **E2E tests** (Playwright) for GraphQL subscriptions  

To run the full suite:

```bash
pnpm test && pnpm k6 run k6/fanout.js
