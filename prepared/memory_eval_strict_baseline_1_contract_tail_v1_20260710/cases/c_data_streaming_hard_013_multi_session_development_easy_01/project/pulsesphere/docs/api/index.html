PulseSphere C SDK – API Reference

The PulseSphere C SDK enables low-latency integration with the PulseSphere Event Fabric. It provides a minimal, zero-GC runtime with lock-free datastructures suitable for extreme throughput scenarios.

The API is divided into several modules, each encapsulating a specific stage of the data pipeline: ingestion, validation, enrichment, storage, and metrics. The design follows Single Responsibility and Strategy patterns, making it easy to swap components without recompilation.

Quick Start

# Build
$ mkdir build && cd build
$ cmake .. -DCMAKE_BUILD_TYPE=Release
$ make -j$(nproc)

# Run unit tests
$ ctest --output-on-failure

#include <pulsesphere/pulse.h>

static void on_event(const pulse_event *evt, void *user_data)
{
    printf("[callback] user=%s payload=%.*s\n",
           evt->actor_id,
           (int)evt->payload.len,
           evt->payload.ptr);
}

int main(void)
{
    pulse_cfg cfg = pulse_cfg_default();
    cfg.cluster_uri = "ps://cluster-01.streaming.internal:7623";
    cfg.auth_token  = getenv("PULSE_AUTH_TOKEN");

    pulse_init(&cfg);

    pulse_subscription sub = {
        .topic     = "social/global",
        .on_event  = on_event,
        .user_data = NULL,
    };

    pulse_subscribe(&sub);

    /* Main loop -------------------------------------------------------- */
    while (!pulse_should_shutdown())
        pulse_poll(50 /* ms */);

    pulse_shutdown();
    return 0;
}

Thread Safety

All functions in the PulseSphere SDK are thread-safe unless explicitly documented otherwise. Internally the library uses pthread_once for global initialization and lock-free ring buffers for producer/consumer queues.

Module — Ingestion

The ingestion module captures raw social pulses over WebSockets, REST webhooks, or binary TCP frames and normalizes them to the unified pulse_event structure.

Module — Validation

Validation ensures schema compliance, detects duplicates, and performs signature verification.

Module — Enrichment

Enrichment applies geo-tagging, NLP-based language detection, toxicity scoring, and user-reputation augmentation.

Module — Storage

The storage module writes curated pulses into distributed object stores, columnar analytics warehouses, and on-disk WALs for recovery.

Struct — pulse_event

typedef struct pulse_event {
    uint64_t            timestamp_ns; /* Event creation time (source).    */
    pulse_type          type;         /* Like, comment, share, …          */
    char                actor_id[40]; /* UTF-8 user identifier.           */
    pulse_buf           payload;      /* Event-specific JSON payload.     */
    pulse_validation_id validation;   /* ID of the validation strategy.   */
    pulse_enrichment_id enrichment;   /* ID of the enrichment strategy.   */
    uint32_t            crc32;        /* Wire CRC for detection of tamper.*/
} pulse_event;

pulse_init

/**
 * Initialize the PulseSphere runtime.
 *
 * @param cfg   Pointer to a fully-initialized pulse_cfg object.
 *
 * @return 0 on success; non-zero errno-style code on failure.
 *
 * Thread-safety: Safe to call from a single thread only, prior to spawning
 * worker threads.
 */
int pulse_init(const pulse_cfg *cfg);

pulse_shutdown

/**
 * Gracefully shuts down the PulseSphere runtime, flushing any outstanding
 * buffers and releasing OS resources.  May block for up to
 * PULSE_MAX_SHUTDOWN_MS.
 */
void pulse_shutdown(void);

/**
